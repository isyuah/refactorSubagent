统一配置源

两个配置域，一套合并引擎

原来的分层配置只服务"阈值"这一件事：层路径、合并、覆盖值解析、报错文案全是 limit 专用。 现在引擎被抽出来复用，新增一个配置域只需要提供四样东西。

src/config/layers.ts · 引擎
层路径展开、JSON 读取、深合并（null 是显式值而非缺省）、 a.b.c=value 覆盖与未知键点名、来源/缺失文件记账、按域名词生成错误文案。
域 = schema + 路径 + 值解析 + 名词
limits：数值或 null；pipeline：字符串/数值。 两者共用同一套优先级，不会各自发明顺序。
域文件承载什么变更
limits .refactor/limits.json 超时与资源上限（会话预算、构建/测试预算、命令预算、进程与字节上限） 行为与报错文案逐字不变，改为基于引擎
pipeline .refactor/pipeline.json 每段流程的"输入从哪来"：预置 workflow 入口、候选补丁、复用的候选分支 新增
为什么要抽引擎 两个域如果各自实现一遍层合并，迟早会在"null 算不算值""typo 要不要报错""显式文件排在项目层前还是后"上分叉。 现在这些语义只写在 layers.ts 一处；单测里 tests/pipeline-config.test.ts 覆盖了默认全 AI、 单阶段替换、写错键被点名拒绝、覆盖优先级、模式冲突、空数组被拒六种情形。

规则内容为什么
阶段只能"叫停" 槽返回 { halt: true, reason }，由组合器统一调 abort() 状态机的推进权只在宿主，槽拿不到 Orchestrator
宿主不变量不可替换 状态转移、候选改动集测量（git add/commit/diff）、门禁顺序（探测 ready / 改动非空 / 声明集非空）、worktree 清理与提升 阶段只能产出"流程的下一个输入"，改不出自己没做过的成绩
判定可注入但要留痕 注入 verify 时写 stage-provenance.json 并在返回值里标 verification_authoritative:false 注入不是安全问题（调用方本就能直接操作状态机），是可读性问题：一次 ACCEPT 必须能回答"真判还是演的"

4.3 顺手修掉的一个 fail-open 缺陷（harness 侧）

写判据时发现：ctx.expect(name, value) 用参数类型判断重载——第二个参数只要是字符串就被当成 relation， 值被丢成 undefined，两侧 undefined 恒等，行为不同也判一致。 也就是说所有"字符串期望"（stdout 文本、版本号、哈希）都在静默失效。已改为按参数个数判定， 并由 tests/stage-flow.test.ts 的 REJECTED 用例兜住（修复前该用例为 ACCEPTED）。 另外给自驱动路径的验证结果补上 expectationComparison，判定结论不再只存在于 artifact 文件里。

libuv/（7 MB）嵌套 git 检出，git 不支持把仓库塞进仓库；而材料只有 100 KB 上游 v1.52.1 + baseline/overlay/（命令写在 baseline/README）
runs/（139 MB）每次运行的证据，可重跑生成跑一次就有；历史批次是当时的记录
testset/.cache/（133 MB）热构建槽位，随时可删删掉后第一批重新冷构建（6m18s vs 3m55s）
重建的检出 sha 必然不同，判定依赖的是内容摘要 按 overlay 重建的基线提交哈希与 c6154e7 不同（提交时间/作者不同），所以 runner 新增 --baseline-commit <ref> 让重建检出顶替钉死的 sha；真正决定判据成立与否的是 PINS.json 与 inventory 里的逐文件 sha256——--list 与自检会校验它们。
搬迁顺带逼出的一个健壮性修复 槽位被移动后，里面 worktree 的 .git 仍指向旧路径，复用路径会对每条 git 命令报错。 现在自愈：丢掉坏目录、prune、重建（tests/worktree-reuse.test.ts 3 条，含"注册丢失后重建"）。 也是这次搬迁第一次让 state.json.abort_reason 派上用场——一行就点明了失败原因。
