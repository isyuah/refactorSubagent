为这份 libuv v1.52.1 检出写一套 build / test workflow，用来冻结 **src/inet.c（uv_inet_ntop / uv_inet_pton 及其 static 内部函数）** 的行为：
构建产物要求 build/uv_run_tests_a 加上 ctx.facts.host.executable_suffix，以及 build/libuv.a。通过 ctx.facts.host.platform 获取实际系统：Windows 为 win32，Linux 为 linux；CMake 使用 Ninja、GCC、Debug 和 -DBUILD_TESTING=ON。仅 Windows GCC 15 需要 -Wno-error=incompatible-pointer-types -Wno-error=discarded-qualifiers，否则 src/win/util.c:630 直接报错。判据编译的系统库及平台 ABI 期望也必须匹配当前系统。
测试判据由你自己设计：跑哪些用例、声明哪些期望（两侧一致 + 绝对值两种都要有）、以及怎么防止判据材料本身被改。仓库自带的 test/ 套件可用（静态 runner 加 <case> 参数，一个用例一个进程；--list 列出当前平台的全部用例名）。
不允许：修改 src/**、include/**、test/**、CMakeLists.txt；只产出 workflow 源。
注意：目标缓冲区规则（size >= strlen(渲染)+1 才成功，否则 UV_ENOSPC 且目标缓冲区一个字节都不写）、IPv6 单个零组不压缩、v4-mapped 用点分十进制——这些是必须保持的行为。
