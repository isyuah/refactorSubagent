# 学习路线 —— 从零到看懂全部代码

> 使用前提：所有代码请在 `代码教程/` 下读注释版；本路线每一步都给出阅读顺序、预计时间和自测题。
> 能答出自测题 = 这一关通过。全部走完约需 3~5 个学习日。
>
> ⚠️ **2026-09 架构改版（B 方案：声明制依赖）**：旧的 chooser / 模板生成 /
> resolve-workflows 三源决策已删除，AI 层改为 test-writer 主会话 + dep-registry
> MCP 三工具 + build-writer 子代理 + 宿主按 DeclaredBuildSet 声明执行 N≥0 个 build。
> 本路线已同步；建议先读 `docs/b-subagent-workflow.md` 原文，再按下表走。

## 阶段 0：建立大局观（0.5 小时，不动代码）

| 顺序 | 材料 | 目标 |
|---|---|---|
| 0.1 | 《零基础看懂教程.md》§1.1-1.3 | 能复述"Claude 动手、程序裁决"和 10 步旅程 |

| 0.4 | `bun run scripts/e2e-dashboard.ts` 后打开浏览器 | 亲眼看看 Dashboard 长什么样 |

## 阶段 1：数据的世界 —— src/artifacts/（半天）

先读数据再读逻辑：这个项目里"一切产出都是带 kind 的 JSON"。

| 顺序 | 文件 | 看点 |
|---|---|---|
| 1.1 | `artifacts/common.ts` | Zod 入门：RelPath/hash 是什么 |
| 1.2 | `behavior-contract.ts` | "行为保持"到底指哪些通道 |
| 1.3 | `scope-manifest.ts` | editable / readable / forbidden 三类范围 |
| 1.4 | `dependency-manifest.ts` | 8 类依赖、8 种隔离策略 |
| 1.5 | `test-spec.ts` → `observation-trace.ts` → `comparison-result.ts` | 测试用例 → 观测 → 对比 的演化线 |
| 1.6 | `environment-spec.ts` + `host-preflight.ts` | "模型建议" vs "程序测量"的区别 |
| 1.7 | `ctest-suite.ts` | 最常用的一族：Spec/Result/ComparisonResult |
| 1.8 | `expectation-suite.ts` | 自驱动 TestWorkflow 的期望怎么持久化 |
| 1.9 | `patch-record.ts` + `workflow-resolution.ts` | 代码改动记录、三源决策记录 |
| 1.10 | `refactor-task.ts` | 大而全的实战样例（libuv 固定任务） |
| 1.11 | `index.ts` | 桶导出是什么 |

**自测**：① `superRefine` 和 `.transform` 分别干什么用？② `workflow-resolution` 里为什么 build 的 `build_workflow` 必须是 null、test 必须非 null？③ CTest 报告里的 `total: 2` 指什么？

## 阶段 7：用测试倒着学（贯穿）

`tests/state-machine.test.ts`（R1-R7）、`expectation-state-machine.test.ts`（对比→裁决）、
`workflow-plan.test.ts`（plan 状态机）、`test-executor.test.ts`（两侧配对）、

`resolve-declared.test.ts` + `curator.test.ts` + `build-writer.test.ts`（B 方案五族新测试）。

## 学完之后

1. 挑《零基础看懂教程.md》任务清单里的一项，写出：现状（哪几行）→ 方案 → 要碰的文件；
2. 给 `tests/` 加一个失败用例复述你发现的问题；
3. 跑通一条 e2e 并用 Dashboard 讲清整个过程——能讲清楚，就是真的懂了。
