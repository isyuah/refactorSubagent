# 注释编写规范（教程编写者必读）

> 本目录（`代码教程/`）是整个仓库源码的**注释版副本**：目录结构与原仓库完全一致，代码内容与原文件**逐字一致**，只是在旁边新增了大量中文注释，帮助零基础读者看懂。
> 本规范保证所有文件由不同人编写时风格统一。

## 一、铁律（违反即返工）

1. **代码一个字符都不能改**。不删行、不改名、不重排、不加空行改动原结构。你唯一能做的就是**新增注释**。
2. 注释只能放在语法合法的位置：语句与语句之间、某行代码的行尾（`// …`）、函数/类型/常量的上方（`/* … */` 或 `// …`）。**绝不许插进表达式/参数列表中间**。
3. 事实必须来自代码本身或《零基础看懂教程.md》，不确定就去读相关文件核实，**不许编造**。
4. 不修改 `代码教程/` 之外的任何文件；不运行测试；不 git 操作。

## 二、三层注释结构（每个文件都要有）

### 第 1 层：文件头总览（放在文件第一行之前）

```ts
/* ═══════════════════════════════════════════════════════════════════
 * 【文件总览】src/orchestrator/orchestrator.ts —— fail-closed 状态机
 *
 * 【这个文件是干什么的】
 *   用大白话说明职责……
 * 【在整个项目里的位置】
 *   谁调用它（上游）、它调用谁（下游）、它产出的数据去哪
 * 【先修知识】
 *   读这个文件前建议先看懂哪几个文件/概念
 * 【本文件是教程注释版】
 *   原文件：src/orchestrator/orchestrator.ts（代码与本文件一致，仅多注释）
 * ═══════════════════════════════════════════════════════════════════ */
```

### 第 2 层：函数/类型/常量级（每个导出都要覆盖）

```ts
// ── runAgent：驱动一次 Claude 会话（本文件最核心的函数）──────────────
// 【作用】…
// 【参数】o: DriverOptions —— 逐个解释重要字段
// 【返回】Promise<DriverRun> —— 解释字段
// 【语法】只在本文件第一次出现的新语法才讲，比如 async/await、泛型、可选链 ?.
// 【关系】谁调用它、它内部调用了谁、失败时会发生什么
```

### 第 3 层：行内注释（讲"这一行在干嘛/为什么"）

```ts
const q = query({ ... });           // ← 真正发起 Claude 会话；返回一个可迭代的会话对象
persistSession: false,              // ← 每次都是全新会话，不保留历史（这也是 e2e 慢的原因之一）
```

## 三、内容要求（四要素）

每个重要函数/类型的注释都要尽量回答：

| 要素 | 说明 |
|---|---|
| 用到了什么函数 | 它调用了谁（标准库/本项目函数），各自干嘛 |
| 语法是什么 | 小白可能没见过的 TS/JS 语法：泛型、`readonly`、`?.`、`??`、as、satisfies、async/await、Map/Set、模板字符串、解构、Zod 的链式调用……**每个文件里同一种语法只详细讲第一次** |
| 参数/返回值是什么含义 | 逐个解释，包括单位（毫秒！）、可空性、默认值 |
| 在整个项目里是什么关系 | 上游谁调用、下游调用谁、产出给谁用、失败会怎样 |

## 四、语言风格

- 中文、口语化、面向没写过 TypeScript 的读者；
- 打比方可以（"Zod 像海关安检"），但每个概念最多打一次比方；
- 长文件（>400 行）不必逐行注释，覆盖：所有导出、所有函数、所有难懂的行；
- 短文件（<100 行）可以逐行/逐块细讲。

## 五、统一标记

- 文件头用 `/* ═══ … ═══ */`；函数级用 `// ── 名字 ─…─` + `【作用】【参数】【返回】【语法】【关系】`；行内用 `// ←`。
- 特别值得注意的坑用 `// ⚠️ …`；和本项目其他部分有呼应的用 `// 🔗 见 …`。
