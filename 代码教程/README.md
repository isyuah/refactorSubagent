# 代码教程 —— 看懂 refactorSubagent 的每一行代码

> 本目录是仓库源码的**注释版副本**：目录结构与原仓库完全一致，代码逐字相同，只是加满了中文注释（讲语法、讲参数、讲返回值、讲它在项目里的关系）。
>
> ⚠️ 本目录只用来**读**。运行、测试、改动请永远操作仓库原文件（`src/`、`scripts/`…），这里的副本不参与构建。

## 目录对照

| 本目录 | 原目录 | 内容 |
|---|---|---|
| `src/artifacts/` | 同名 | 所有数据结构（Zod Schema），项目里的"每一张表格" |
| `src/orchestrator/` | 同名 | 状态机 + 会话持久化（项目的"流程裁判"） |
| `src/agents/` | 同名 | 驱动 Claude 的代码 + 全部提示词 |
| `src/workflow/` | 同名 | Build/TestWorkflow 子系统（三源决策、能力代理、注册表） |
| `src/runtime/` | 同名 | 流水线与执行（探测、构建、CTest、对比、观测） |
| `src/cli/` | 同名 | 命令行参数解析 |
| `scripts/` | 同名 | 所有可运行入口（demo / e2e） |
| `tests/` | 同名 | bun test 单元测试（看"预期行为"的最好材料） |
| `examples/` | 同名 | 手写 workflow 样例 + 最小 C 示例工程 |
| `web/` | 同名 | Dashboard 前端页面 |

## 怎么用

1. 先读根目录《零基础看懂教程.md》和《原材料-环境-产物-步骤.md》建立大局观；
2. 按《学习路线.md》的顺序逐文件阅读（每条路线都标注了先修关系和自测问题）；
3. 读不懂的语法先看文件头【先修知识】，再搜索本目录其他文件里同一语法的讲法；
4. 《项目结构目录图.md》是全项目的地图，迷路了就回来看它。
