# 库消费者验证

适用于 DLL、共享库、静态库，或没有直接可执行入口的项目。

## build-writer

- 构建当前 worktree 中受影响的真实库目标。可复用项目的相关目标，不要求完整构建所有产物。
- 把消费者 `.c` 与必要的数据/包装构建文件登记为 `materials`。
- 消费者使用项目真实头文件与 API；链接当前侧的库，或按其真实导出方式加载。
  不链接原仓库的旧产物，不把同一个库复制到两侧，不复制目标函数实现。
- 用 `ctx.facts.host.platform` 选择产物形式与参数：Windows DLL/import library，Linux `.so`，macOS `.dylib`。
  库布局与导出名称必须从项目和实际探测确认，不只按扩展名猜。
- 确认运行时加载路径：Windows 可把 DLL 和消费者放在同一目录；Linux/macOS 使用合适的相对 rpath。
  不依赖作者机器的绝对路径或未经允许的环境变量。
- 每次编译/链接都检查 status 和 exitCode，断言库与消费者产物存在。
  汇报准确调用路径、库来源与辅助材料路径。

## test-writer

- 通过消费者实际调用 API，至少覆盖普通输入及本次修改相关边界，观测返回值、输出或可见副作用。
- 先检查加载成功、程序正常结束、用例确实执行，再比较观测。
  消费者报错后输出相同、空输出或两侧都找不到符号，均不能当作通过。
- 使用相同材料和调用协议，值来自当前侧实现；禁止判断自己是哪一侧。
- DLL 消费者测试只证明这些 API 与输入的行为；不要声称它验证了所有宿主集成和 ABI。
